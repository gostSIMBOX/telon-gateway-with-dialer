## Module Overview

**Call State Machine** provides a unified data model for representing call lifecycle across both native telephony (Tele) and VoIP (Pjsip) paths. The Call class manages state transitions, duration calculation, and caller information parsing.

---

## Functional Requirements

### FR-1: Call State Representation

**Description:** The Call class must represent all PJSIP call states uniformly.

**States:**
| State Constant | Description | When Active |
|----------------|-------------|-------------|
| `PJSIP_INV_STATE_NULL` | Initial state | Before INVITE sent/received |
| `PJSIP_INV_STATE_CALLING` | Outgoing | After INVITE sent |
| `PJSIP_INV_STATE_INCOMING` | Incoming | After INVITE received |
| `PJSIP_INV_STATE_EARLY` | Early media | After provisional response |
| `PJSIP_INV_STATE_CONNECTING` | Connecting | After 2xx response |
| `PJSIP_INV_STATE_CONFIRMED` | Established | After ACK |
| `PJSIP_INV_STATE_DISCONNECTED` | Terminated | Call ended |

**Source:** `src/modules/call.js`

### FR-3: Remote Party Information

**Description:** Extract and format caller/callee information from SIP/tel URIs.

**URI Formats to Parse:**
```javascript
// SIP URI with display name
"John Doe" <sip:12345@sip.example.com>
→ getRemoteName() = "John Doe"
→ getRemoteNumber() = "12345"

// SIP URI without name
sip:12345@sip.example.com
→ getRemoteName() = null
→ getRemoteNumber() = "12345"

// Tel URI
tel:+79001234567
→ getRemoteName() = null
→ getRemoteNumber() = "+79001234567"

// Tel URI with URL encoding
tel:%2B79219542499
→ getRemoteNumber() = "+79219542499"
```

**Formatted Output:**
```javascript
getRemoteFormattedNumber()
→ "John Doe <12345>"  (if name present)
→ "12345"             (if only number)
→ remoteUri           (fallback)
```

**Source:** `src/modules/call.js` constructor

### FR-4: Call Duration Calculation

**Description:** Calculate call duration in real-time without continuous state updates.

**Duration Types:**
- **Total Duration:** Time since call object creation
- **Connect Duration:** Time since call was answered (connected)

**Live Calculation:**
```javascript
getTotalDuration()      // → seconds (integer)
getConnectDuration()    // → seconds (integer, -1 if not connected)
```

**Edge Cases:**
- Disconnected calls: Return last known duration
- Not-yet-connected calls: Return -1 or 0
- Ongoing calls: Calculate from timestamp offset

**Source:** `src/modules/call.js`

### FR-5: Duration Formatting

**Description:** Format duration as human-readable "MM:SS" or "HH:MM:SS" string.

**Format:**
```javascript
getFormattedTotalDuration()     // → "MM:SS" or "HH:MM:SS"
getFormattedConnectDuration()   // → "MM:SS" or "HH:MM:SS"
```

**Examples:**
```javascript
0 seconds      → "00:00"
5 seconds      → "00:05"
65 seconds     → "01:05"
3661 seconds   → "01:01:01"
-1 seconds     → "00:00" (invalid)
NaN            → "00:00" (invalid)
```

## Non-Functional Requirements

### NFR-1: Performance - Live Duration Calculation

**Requirement:** Duration calculation must not cause performance issues when called on every render.

**Implementation:** Use timestamp offset calculation instead of storing/updating duration continuously.

**Performance Target:** < 1ms per calculation.

---

### NFR-2: Memory Efficiency

**Requirement:** Call object should not hold unnecessary references.

**Implementation:** Store only essential data in constructor. Calculate derived values on-demand.

---

### NFR-3: URI Parsing Robustness

**Requirement:** URI parsing must handle malformed URIs gracefully.

**Edge Cases:**
- Missing scheme (tel:, sip:)
- Invalid characters
- URL-encoded characters
- Missing @domain in SIP URI

**Current Status:** ⚠️ **PARTIAL** - Regex may fail on edge cases.

---

### NFR-4: Type Safety

**Requirement:** All methods should return expected types consistently.

**Current Issues:**
- `getRemoteNumber()` can return `null` or `string`
- `getConnectDuration()` can return `number` or `-1`
- No TypeScript types defined

**Recommendation:** Add JSDoc or migrate to TypeScript.
