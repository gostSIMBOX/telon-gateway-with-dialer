## Interface Specifications

### TeleEndpoint Class

**Extends:** `EventEmitter`

#### Constructor

```javascript
constructor()
```

**Side Effects:**
1. Registers `DeviceEventEmitter` listeners:
   - `'teleCallReceived'` → `_onCallReceived()`
   - `'teleCallChanged'` → `_onCallChanged()`
   - `'teleCallRemoved'` → `_onCallTerminated()`

#### Methods

##### `start(configuration: Object): Promise<Object>`

Initializes the telephony module.

**Parameters:**
- `configuration` - Configuration object passed to native module (currently unused)

**Returns:** `Promise<{ calls: Call[], ...extra }>`

**Resolution:**
- Success: `resolve({ calls: Call[], ...extraData })`
- Failure: `reject(errorData)`

---

**Implementation:**

##### `Rec(data: Object): void`

**Private.** Process raw native module callbacks and emit appropriate events.

**Data Format:**
```javascript
{
  action: 'TeleService',
  extra1s: string,  // Event type
  extra1i: number,  // Call state code
  extra1l: number,  // Timestamp
  extra2l: number,  // Connection timestamp
  extra3s: string   // Remote URI
}
```

**State Machine:**
```javascript
STATE_CONNECTING (9)   → call.incoming = false, state = CALLING
STATE_RINGING (2)      → call.incoming = true,  state = INCOMING
STATE_DIALING (1)      → state = EARLY
STATE_ACTIVE (4)       → connectTime = extra2l, state = CONFIRMED
STATE_DISCONNECTED (7) → state = DISCONNECTED
```

### Tele Class

**Purpose:** High-level wrapper around TeleEndpoint with dialer management.

#### Constructor

```javascript
constructor()
```

**Initialization Sequence:**
1. Create `ReplaceDialer` instance
2. Check `isDefault()` → `setDefault()` if needed
3. Create `Endpoint` instance (from react-native-tele)
4. Call `tEndpoint.start()` to get initial state
5. Create `TeleEndpoint` instance
6. Subscribe to TeleEndpoint events:
   - `call_received` → `parent.onCallReceived()`
   - `call_terminated` → `parent.onCallTerminated()`
   - `call_changed` → `parent.onCallChanged()`

**Critical:** Requires `parent` property to be set externally:
```javascript
this.tele = new Tele();
this.tele.parent = this;  // Required!
```

## State Machine Specification

### Call Lifecycle

```
[NULL] ──outgoing call──► [CALLING] ──180 Ringing──► [EARLY]
   │                          │                         │
   │                          │                         │ 200 OK
   │                          │                         ▼
   │                          │                   [CONNECTING]
   │                          │                         │
   │                          │                         │ ACK
   │                          │                         ▼
   │                          └─────────────────► [CONFIRMED]
   │                                                    │
   │                                                    │ BYE
   │                                                    ▼
   └────────────────────────────────────────────► [DISCONNECTED]
```

### Android State Mapping

| Android Constant | Value | PJSIP State | Description |
|------------------|-------|-------------|-------------|
| `STATE_CONNECTING` | 9 | `PJSIP_INV_STATE_CALLING` | Outgoing call initiating |
| `STATE_RINGING` | 2 | `PJSIP_INV_STATE_INCOMING` | Incoming call (user must answer) |
| `STATE_DIALING` | 1 | `PJSIP_INV_STATE_EARLY` | Outgoing call, early media |
| `STATE_ACTIVE` | 4 | `PJSIP_INV_STATE_CONFIRMED` | Call established (2-way audio) |
| `STATE_DISCONNECTED` | 7 | `PJSIP_INV_STATE_DISCONNECTED` | Call ended |
| `STATE_DISCONNECTING` | 10 | `PJSIP_INV_STATE_DISCONNECTED` | Call termination in progress |

## Event Contract

### Native → JavaScript Events

**Event:** `teleCallAdded`

**Payload:**
```javascript
{
  action: 'TeleService',
  extra1s: 'onCallAdded',
  extra1i: STATE_*,
  extra1l: creationTimestamp,
  extra3s: remoteUri
}
```

**Handler:** `TeleEndpoint.Rec()` creates Call object, emits `call_received`

---

**Event:** `teleStateChanged`

**Payload:**
```javascript
{
  action: 'TeleService',
  extra1s: 'onStateChanged',
  extra1i: STATE_*,
  extra2l: connectTimestamp
}
```

**Handler:** `TeleEndpoint.Rec()` updates Call state, emits `call_changed`

---

**Event:** `teleCallRemoved`

**Payload:**
```javascript
{
  action: 'TeleService',
  extra1s: 'onCallRemoved'
}
```

**Handler:** `TeleEndpoint.Rec()` clears currentCall, emits `call_terminated`

## Error Handling

### Current Implementation

**Promise-based initialization:**
```javascript
start(configuration) {
  return new Promise((resolve, reject) => {
    NativeModules.TeleModule.start(configuration, (successful, data) => {
      if (successful) {
        resolve(data)
      } else {
        reject(data)
      }
    })
  })
}
```

**Missing:**
- ❌ No error handling in event listeners (`_onCallReceived`, etc.)
- ❌ No error handling in `Rec()` method
- ❌ No retry logic for native module failures

### Recommended Improvements

```javascript
_onCallReceived(data) {
  try {
    this.emit("call_received", new Call(data))
  } catch (error) {
    console.error("TeleEndpoint: Error in call_received handler", error)
    // Optionally emit error event
    this.emit("error", { type: 'call_received', error, data })
  }
}
```

## Performance Considerations

### Duration Calculation

**Live calculation** using local timestamps:

```javascript
getTotalDuration() {
  const time = Math.round(new Date().getTime() / 1000)
  const offset = time - this._constructionTime
  return this._totalDuration + offset
}
```

**Rationale:** Avoids continuous state updates from native layer. UI components call this method on each render for real-time duration display.

**Potential Issue:** `_constructionTime` is set in Call constructor using `new Date()`, which may drift from actual native call start time.

## Migration Notes

### Known Issues

1. **Duplicate endpoint classes:** Both `Tele` and `TeleEndpoint` exist. Consider consolidation.

2. **Commented-out code:** `tele_endpoint.js` contains ~200 lines of commented code (lines 100-300). Should be removed or documented.

3. **Inconsistent state management:** `Call` object has both `_state` and `state` properties. Only `_state` is used consistently.

4. **Missing TypeScript types:** All files are plain JavaScript with JSDoc. Consider TypeScript migration.
