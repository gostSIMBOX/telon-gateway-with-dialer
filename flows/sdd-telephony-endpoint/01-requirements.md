## Module Overview

**Telephony Endpoint** provides React Native integration with Android's native telephony system, enabling the app to function as the default dialer and manage calls through the system telephony service.

---

## Functional Requirements

### FR-1: Default Dialer Replacement

**Description:** The application must be able to set itself as the default Android dialer to receive all call events system-wide.

**Acceptance Criteria:**
- ✅ Check if app is currently default dialer via `ReplaceDialer.isDefault()`
- ✅ Request default dialer status via `ReplaceDialer.setDefault()` if not default
- ✅ Log dialer status changes for debugging

**Source:** `src/modules/tele.js`

---

### FR-2: Call Event Subscription

**Description:** The endpoint must subscribe to native telephony events emitted by Android's TeleModule.

**Events:**
| Event Name | Payload | Trigger |
|------------|---------|---------|
| `teleCallReceived` | Call data object | New incoming/outgoing call detected |
| `teleCallChanged` | Call data object | Call state changed (dialing → active, etc.) |
| `teleCallRemoved` | Call data object | Call ended/removed from system |

**Source:** `src/modules/tele_endpoint.js`

---

### FR-3: Call State Management

**Description:** Maintain current call state and translate Android telephony states to PJSIP-compatible states for UI consistency.

**State Mapping:**
| Android State | Code | PJSIP State |
|---------------|------|-------------|
| STATE_CONNECTING | 9 | PJSIP_INV_STATE_CALLING |
| STATE_RINGING | 2 | PJSIP_INV_STATE_INCOMING |
| STATE_DIALING | 1 | PJSIP_INV_STATE_EARLY |
| STATE_ACTIVE | 4 | PJSIP_INV_STATE_CONFIRMED |
| STATE_DISCONNECTED | 7 | PJSIP_INV_STATE_DISCONNECTED |
| STATE_DISCONNECTING | 10 | PJSIP_INV_STATE_DISCONNECTED |

**Source:** `src/modules/tele_endpoint.js` → `Rec()` method

---

### FR-4: Call Control Operations

**Description:** Provide methods to control active calls via native telephony commands.

**Operations:**

| Operation | Direction | Native Method |
|-----------|-----------|---------------|
| `answerCall(call)` | Incoming | `NativeModules.TeleModule.answerCall()` |
| `declineCall(call)` | Incoming | `NativeModules.TeleModule.declineCall()` |
| `hangupCall(call)` | Outgoing | `NativeModules.TeleModule.hangupCall()` |

**Source:** `src/modules/tele_endpoint.js`

---

### FR-5: Call Object Construction

**Description:** Convert raw native call data into standardized Call objects with consistent API.

**Call Data Extraction:**
- Remote URI parsing (extract name and number from SIP/tel URIs)
- State tracking (current state, connection time, creation time)
- Duration calculation (total duration, connected duration)

**Source:** `src/modules/call.js`, `src/modules/tele_endpoint.js`

---

### FR-6: Permission Management

**Description:** Request required Android permissions for telephony functionality.

**Required Permissions:**
- `READ_CALL_LOG` - Access call history
- `READ_PHONE_STATE` - Monitor phone state changes

**Source:** `src/index.js`

## Non-Functional Requirements

### NFR-1: Event-Driven Architecture

**Requirement:** All call updates must flow through EventEmitter pattern for decoupled architecture.

**Rationale:** Enables multiple subscribers (UI, analytics, call recording) without tight coupling.

---

### NFR-2: State Synchronization

**Requirement:** Call state must be synchronized between native Android and React Native layers in real-time.

**Implementation:** `DeviceEventEmitter` listeners update TeleEndpoint state immediately upon native events.

---

### NFR-3: Error Resilience

**Requirement:** Native module failures should not crash the JavaScript layer.

**Current Status:** ⚠️ **PARTIAL** - Error handling exists in `start()` Promise rejection, but event listeners have no try-catch.

## Open Questions

1. **Why two endpoint classes?** Both `Tele` and `TeleEndpoint` exist with overlapping responsibilities. Is this intentional separation or legacy code?

2. **Missing error handling:** Event listeners (`_onCallReceived`, etc.) have no error boundaries. Should be addressed.

3. **PJSIP state compatibility:** Why map Android states to PJSIP states if not using PJSIP library? Historical reason or future integration?
