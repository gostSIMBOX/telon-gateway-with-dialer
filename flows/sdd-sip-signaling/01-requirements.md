## Module Overview

**SIP Signaling** provides VoIP (Voice over IP) call capabilities via the PJSIP library, enabling internet-based calls as an alternative to native cellular telephony.

---

## Functional Requirements

### FR-1: SIP Endpoint Initialization

**Description:** The module must initialize a PJSIP endpoint to handle SIP protocol communication.

**Acceptance Criteria:**
- ✅ Create `Endpoint` instance from `react-native-sip`
- ✅ Call `endpoint.start()` to initialize native PJSIP stack
- ✅ Handle initialization errors gracefully

**Source:** `src/modules/pjsip.js`

---

### FR-2: SIP Account Registration

**Description:** Register with a SIP server to enable incoming/outgoing VoIP calls.

**Configuration Parameters:**
| Parameter | Required | Description |
|-----------|----------|-------------|
| `name` | Yes | Display name for caller ID |
| `username` | Yes | SIP account username |
| `password` | Yes | SIP account password |
| `domain` | Yes | SIP server domain/IP |
| `regServer` | No | Registration server (defaults to domain) |
| `transport` | No | UDP/TCP/TLS (default: TCP) |
| `regTimeout` | No | Registration refresh interval (default: 3600s) |
| `regOnAdd` | No | Auto-register on account creation (default: true) |

**Source:** `src/modules/pjsip.js` → `init()`

### FR-5: SIP Event Subscription

**Description:** Subscribe to SIP endpoint events for call lifecycle management.

**Events:**
| Event | Payload | Trigger |
|-------|---------|---------|
| `registration_changed` | Account object | SIP registration state changes |
| `connectivity_changed` | Boolean (online) | Network connectivity changes |
| `call_received` | Call object | Incoming SIP call |
| `call_changed` | Call object | Call state updated |
| `call_terminated` | Call object | Call ended |
| `call_screen_locked` | Call object | Screen lock request (Android) |

**Source:** `src/modules/pjsip.js` → `init()`

## Open Questions

1. **Why two SIP modules?** Both `pjsip.js` and `pjsip_old.js` exist. The latter is incomplete and should be removed.

2. **Why React Component?** `Pjsip` extends Component but doesn't use React lifecycle. Should be a plain class.

3. **Credential security:** Why are credentials hardcoded instead of using secure storage?

4. **Event handler bug:** Why does `call_changed` call `onCallTerminated()` instead of `onCallChanged()`?

5. **Dual-path coordination:** How does the app decide when to use Tele (native) vs Pjsip (SIP)? This decision logic is not visible in the analyzed code.

## Appendix: SIP Call Flow

```
Registration Phase:
  Pjsip → REGISTER → SIP Server
  Pjsip ← 200 OK ← SIP Server
  
Incoming Call:
  Pjsip ← INVITE ← SIP Server
  Pjsip → 100 Trying → SIP Server
  Pjsip → 180 Ringing → SIP Server
  Pjsip ← 200 OK ← SIP Server (after answer)
  Pjsip → ACK → SIP Server
  [RTP media stream established]
  Pjsip ← BYE ← SIP Server (or Pjsip → BYE)
  Pjsip → 200 OK → SIP Server
  
Outgoing Call:
  Pjsip → INVITE → SIP Server
  Pjsip ← 100 Trying ← SIP Server
  Pjsip ← 180 Ringing ← SIP Server
  Pjsip ← 200 OK ← SIP Server (after answer)
  Pjsip → ACK → SIP Server
  [RTP media stream established]
```
